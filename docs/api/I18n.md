# i18n API

The **i18n** module is the locale registry behind every string wui renders on its own
initiative — toolbar tooltips, dialog buttons, property-row labels, the `Page 3 / 8`
strip under a paginated sheet. None of those come from a call site the host controls,
so before this module an application written in Malay still had English in the middle
of its own UI.

Three packs ship with the package: **English**, **Chinese (Simplified and Traditional)**
and **Bahasa Malaysia**. Only English is bundled. The rest are filed as dynamic imports
and fetched the first time something asks for them, so a build that never switches
language never downloads a byte of translation.

---

# Import

### TSX / TS

```ts
import { t, tx, setLocale, availableLocales, localized } from "@woby/wui";
```

The whole module is re-exported from the package barrel. Importing it registers English
eagerly and files the other three as loaders — there is no initialisation call.

### Web Component

```ts
import "@woby/wui"; // registers <wui-language-switch> along with everything else
```

# The two catalogues

There are two kinds of string in this codebase, and they are looked up differently.

| Catalogue | Function | Key | Used for |
| --------- | -------- | --- | -------- |
| **Keyed** | `t('editor.bold')` | A stable id | Everything wui itself renders |
| **English-as-key** | `tx('Badge Content')` | The English text | Plugin `label:` and `hint:` strings |

The split is not stylistic. Keyed ids mean rewording the English never silently
un-translates the other packs — change `Bold` to `Bold text` and `editor.bold` still
resolves everywhere. But the ~265 `label:` / `hint:` strings in `WuiPlugins.ts` and
`PageBlockPlugins.ts` are a different problem: the interesting ones are not ours. A host
that registers its own editor plugin writes its own English labels, and nobody is going
to go back and add message ids to somebody else's plugin. Looking the English up
*directly* means a locale pack can translate a third-party plugin the plugin has never
heard of, and an untranslated string degrades to the English its author wrote — which is
precisely what it rendered before this module existed.

Because identity is the fallback, `tx` is safe to wrap around anything. That also settles
what is deliberately **not** translated, and why nothing had to be excluded by hand:

- **Font family names.** `Georgia` is a typeface, not a word.
- **CSS property names.** A designer types `flex-direction`; translating it breaks the
  thing they typed.
- **Formula and GIS function names** in `DropdownEditor` — `Abs`, `Concat`. No
  spreadsheet translates those either.
- **The `−` / `+` zoom glyphs.** Already language-neutral.

They pass through untouched unless a pack deliberately claims them.

# API Overview

## Translation

| Function | Signature | Description |
| -------- | --------- | ----------- |
| **t** | `(key, params?) => string` | Keyed lookup. A missing id returns the id — `editor.bold` on a button is an obvious bug report; an empty tooltip is an invisible one. |
| **tx** | `(text, params?) => string` | English-as-key lookup. Falls back to its own argument. `null` / `undefined` return `""`. |
| **tn** | `(key, count, params?) => string` | Plural form via `Intl.PluralRules`. Looks up `key.one` / `key.other` / whatever the language needs, falling back to `key.other`. |
| **localized** | `(given, key, params?) => Observable<string>` | A prop's own value if the caller set one, the catalogue otherwise — as a memo. |
| **localizedText** | `(given, english) => Observable<string>` | `localized`, against the English-text catalogue. |

Parameters are substituted into `{braces}`: `t('editor.page.label', { page: 3, total: 8 })`
against `Page {page} / {total}`.

## Registry

| Function | Signature | Description |
| -------- | --------- | ----------- |
| **registerLocale** | `(pack, opts?) => void` | Add a pack, or **merge** into one already registered. Later keys win. |
| **registerLocaleLoader** | `(code, loader, meta?) => void` | File a pack to be fetched on demand. |
| **loadLocale** | `(code) => Promise<LocalePack \| undefined>` | Fetch and register without switching. Idempotent and concurrent-safe. |
| **setLocale** | `(code) => Promise<void>` | Switch, loading the pack first if needed. |
| **unregisterLocale** | `(code) => void` | Drop a pack. |
| **availableLocales** | `() => LocaleInfo[]` | Every language on offer, loaded or merely filed. Reactive. |
| **getLocales** | `() => Observable<Record<code, LocalePack>>` | The registry itself. |
| **onLocaleChange** | `(fn) => () => void` | Imperative subscription. Returns an unsubscribe. |

## State and helpers

| Export | Type | Description |
| ------ | ---- | ----------- |
| **locale** | `Observable<LocaleCode>` | The language in force. Read it in a binding; write it through `setLocale`. |
| **defaultLocale** | `Observable<LocaleCode>` | Last resort before the key itself. Defaults to `en`. |
| **normalizeLocale** | `(code) => LocaleCode` | Fold a tag onto a registered pack. |
| **detectLocale** | `() => LocaleCode` | Best match for `<html lang>` then `navigator.languages`. |
| **applyDetectedLocale** | `() => Promise<LocaleCode>` | Detect and switch, once, at start-up. |
| **localeDir** | `() => 'ltr' \| 'rtl'` | Writing direction of the current language. |
| **formatNumber** | `(n, opts?) => string` | `Intl.NumberFormat` against the current locale. |
| **formatDate** | `(d, opts?) => string` | `Intl.DateTimeFormat` against the current locale. |
| **formatList** | `(items, opts?) => string` | `Intl.ListFormat` against the current locale. |

The three `Intl` wrappers exist so call sites read the current locale reactively rather
than each reaching for `navigator.language`. A page that has switched to Malay should not
still be printing `1,234.5` because the browser was installed in English.

# Types

## LocalePack

```ts
interface LocalePack {
    code: LocaleCode            // canonical tag — zh-Hans, not zh_CN
    name: string                // the language's name *in that language*
    english?: string            // the English name, for English-language chrome
    dir?: 'ltr' | 'rtl'         // only rtl does anything
    fallback?: LocaleCode       // tried before the default locale
    messages?: Record<string, string>   // read by t()
    text?: Record<string, string>       // read by tx()
}
```

Both catalogues are optional. The English pack ships **no** `text` map at all — `tx`
already returns its argument, so all ~265 plugin strings already render correctly in
English without a single entry. A pack that only wants to fix a handful of tooltips can
ship `messages` alone.

`name` is an endonym on purpose. Someone looking for Chinese in a menu is looking for
中文, not for the word "Chinese".

## LocaleInfo

```ts
interface LocaleInfo {
    code: LocaleCode
    name: string
    english?: string
    loaded: boolean   // false while only a loader is filed
}
```

`loaded: false` is what lets a picker list a language nobody has paid for yet. Without it
the menu could only offer whatever had already been downloaded, which defeats the point
of lazy loading — the first switch would have nothing to switch to.

# Internal Logic

## Module-level state

The registry is module-level for the same reason `editorLayout` and `scrollerOpen` are:
the toolbar, the property panel and the document surface live in different subtrees —
different shadow roots, often — and none of them is another's parent, so a prop or a
context could not reach across. There is one current language per page, and `locale` is
it.

## The fallback chain

A lookup walks, in order:

1. The current pack.
2. Its declared `fallback`, if any. `zh-Hant` may fall back to `zh-Hans`.
3. `defaultLocale` — English.
4. The key itself (`t`) or the English argument (`tx`).

English is registered **eagerly** rather than filed as a loader precisely because it is
the end of this chain. A lazily-loaded pack missing a key would have nothing to fall back
*to* until English happened to arrive.

## Tag normalisation

`normalizeLocale` tries an alias table first, then progressively shorter prefixes, so
`zh-Hans-CN` finds `zh-Hans` and an unknown `de-AT` still finds `de`. The alias table
folds the regional tags that matter to this package's audience:

| Input | Resolves to |
| ----- | ----------- |
| `zh`, `zh-CN`, `zh-SG`, `zh-MY` | `zh-Hans` |
| `zh-TW`, `zh-HK`, `zh-MO` | `zh-Hant` |
| `ms-MY`, `ms-SG`, `ms-BN`, `zsm` | `ms` |
| `en-GB`, `en-US`, `en-MY`, … | `en` |

A bare `zh` has to resolve to one of the two scripts, because they are not mutually
readable. It resolves to Simplified: that is what browsers sending a bare `zh`
overwhelmingly mean, and what Malaysia and Singapore read.

## Merge, not replace

`registerLocale` **merges** into an existing pack rather than warning and skipping the way
`registerEditorPlugin` does. A second registration of the same code is almost always a
host *extending* a language rather than redefining it: wui ships `zh-Hans`, the
application adds the forty strings of its own chrome under the same tag. Later keys win,
so a host can also override one of ours without forking the pack. Pass
`{ replace: true }` when you really do mean to throw the old one away.

## Loading

`loadLocale` caches the in-flight promise, so ten controls asking for Malay at the same
moment cause one import, not ten. A loader that throws logs a warning and resolves to
`undefined`; the current language is unchanged and the chain keeps serving English.

`setLocale` also writes `document.documentElement.lang`, and `dir` when the pack declares
one.

# Reactivity

`t` and `tx` **read the `locale` observable**. That is the whole mechanism by which a
running editor re-labels itself — and the one mistake this API makes easy.

```tsx
// Correct. A thunk, so it re-runs on every language switch.
<button title={() => t('editor.bold')}>…</button>

// Wrong. A bare call at render time, frozen when the component was built.
<button title={t('editor.bold')}>…</button>
```

The same applies at module scope: a `const LABEL = t('editor.bold')` next to an import is
frozen at import time and will never update.

## localized, for component props

Wrapping every prop in a thunk gets tiring, and there is a second problem underneath it:
a component whose `def()` bakes English into the default cannot tell "the host asked for
Bold" from "nobody said anything and the default is Bold", so the catalogue could never
win. `localized` solves both — the default becomes empty, and the memo it returns can be
passed straight through as a prop value.

```tsx
const def = () => ({ title: $('', HtmlString) as ObservableMaybe<string> })

export const BoldButton = defaults(def, ({ title }) => {
    const label = localized(title, 'editor.bold')
    return <Button title={label} aria-label={label}>…</Button>
})
```

## Imperative consumers

Some text is written into the DOM by hand rather than bound — `PageLayout`'s page-number
strips are built during layout, not rendered by a component. Those subscribe instead:

```ts
onLocaleChange(() => {
    relabelPages()
    flushLayoutSilenced()   // relabelling is not an edit; don't push an undo step
})
```

`onLocaleChange` also fires when a pack lands late. From a subscriber's point of view
that is indistinguishable from the language having just changed: the strings it is
holding were resolved without it.

### Inside a custom element

An element can be removed, so the subscription has to come off with it — the example
above leaks if you paste it into a `connectedCallback`. Keep the unsubscribe beside
whatever other teardown the element already does:

```ts
connectedCallback() {
    if (!this.shadowRoot!.childElementCount) this.build()
    this.sync()
    this.offLocale = onLocaleChange(() => this.sync())
}

disconnectedCallback() {
    this.watching?.disconnect()
    this.offLocale?.()
    this.offLocale = undefined
}
```

The rule that matters is **where the wording lives**. Put it in `sync()`, never in
`build()`: `build()` runs once, so a locale change has to be able to re-label the element
by calling the same method a changed attribute would. Split the two and they drift — the
element comes up in the right language and then never follows a switch, or follows the
switch and comes up wrong.

`wui-watermark` and `wui-page-break` in `src/Editor/PageBlockPlugins.ts` are the worked
examples; both hand-build their shadow trees, so there is no binding to re-run.

# wui-language-switch

The toolbar control. It sits last in the editor's toolbar — it relabels the whole thing,
so it reads as a property of the editor rather than of any one group above it.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| **buttonType** | `ButtonStyles` | `"outlined"` | Passed through to the trigger `Button`. |
| **showName** | `boolean` | `false` | Show the current language's name beside the globe. |
| **class** / **cls** | `JSX.Class` | `""` | Extra classes on the trigger. |

There is deliberately **no `locales` prop**. The menu *is* the registry: it renders
`availableLocales()` inside a thunk, so a pack registered after the editor was built
appears in the menu without anything being re-mounted. Filtering the list is done by not
registering the pack, or by `unregisterLocale`.

Each row shows the endonym plus a muted tag; the active language's row is highlighted.
Picking one closes the menu and fires `setLocale` without awaiting it — the switch is
published the moment the pack lands either way.

# Usage Examples

## Switching language

```ts
import { setLocale, t } from "@woby/wui";

await setLocale("ms");     // fetches the chunk, registers it, publishes
t("editor.bold");          // 'Tebal'
```

Awaiting is optional. Fire-and-forget from a click handler is fine; `await` it when the
very next line depends on the new strings.

## Following the browser

```ts
import { applyDetectedLocale } from "@woby/wui";

await applyDetectedLocale();   // <html lang> first, then navigator.languages
```

`<html lang>` beats the browser's preference list on purpose: a host that set it has made
a decision.

## Building a picker

```tsx
import { availableLocales, locale, setLocale } from "@woby/wui";

<select
    value={locale}
    onChange={(e) => setLocale((e.target as HTMLSelectElement).value)}
>
    {() => availableLocales().map((info) => (
        <option value={info.code}>{info.name}</option>
    ))}
</select>
```

The thunk around `.map` matters — `availableLocales()` is reactive, and a pack filed
after this rendered would otherwise never show up.

## Adding a fourth language

One file and one call, and neither has to live in this package:

```ts
// de.ts
import type { LocalePack } from "@woby/wui";

export const de: LocalePack = {
    code: "de",
    name: "Deutsch",
    english: "German",
    messages: { "editor.bold": "Fett", "editor.italic": "Kursiv" /* … */ },
    text: { "Badge Content": "Badge-Inhalt" /* … */ },
};
```

```ts
import { registerLocaleLoader } from "@woby/wui";

registerLocaleLoader("de", () => import("./de"), {
    name: "Deutsch",
    english: "German",
});
```

The bundler splits `de.ts` into its own chunk. Nothing is fetched until someone picks it,
and `<wui-language-switch>` lists it immediately.

## Extending a shipped language

```ts
import { registerLocale } from "@woby/wui";

// Merges. wui's own zh-Hans keys survive; these are added on top, and a key
// spelled the same as one of ours overrides it.
registerLocale({
    code: "zh-Hans",
    name: "简体中文",
    messages: { "app.save": "保存", "editor.bold": "加粗" },
});
```

## Translating your own plugin

Nothing to do. Write the labels in English as usual —

```ts
registerEditorPlugin({
    tag: "my-widget",
    props: [{ name: "caption", type: "string", label: "Caption", hint: "Shown under the widget" }],
});
```

— and a pack that wants them translated adds them to its `text` map, keyed by that
English. Until one does, they render exactly as written.

# Locale Pack Coverage

| Pack | `messages` | `text` | Loading |
| ---- | ---------- | ------ | ------- |
| `en` | full reference catalogue | — (identity) | eager |
| `zh-Hans` | full | full | on demand |
| `zh-Hant` | full | full | on demand |
| `ms` | full | full | on demand |

`en.ts` is the reference: a key that is not in that file is not translatable anywhere,
because there is nothing for a translator to see. Every other pack is that file with the
right-hand side replaced.
